# 橘猫如何工作

[English](how-jumao-works.md) · 返回 [开始使用](../getting-started.zh-CN.md)

本页讲**产品模型**，不是源码导览。内部管线名称只在需要建立信任时出现。

---

## 同一件事的两层说法

### 给所有人

不会天天写代码，也可以靠 AI 把 App 想法做出来。

橘猫是写代码之前的冷静一步：

1. 你用普通话说想要什么。  
2. 橘猫查看项目文件夹里能看见的信息。  
3. 你得到一份自己能读的计划。  
4. AI 编程工具在同一文件夹里按计划实现。

### 给开发者

橘猫是 AI Coding Agent 前面的**决策与交付控制层**。

| 层级 | 职责 |
|------|------|
| **你** | 目标、品味；真实用户、钱、上线的拍板 |
| **橘猫** | 范围、边界、证据、交接、可选核验 |
| **AI 编程工具** | 改文件、跑工具、实现任务 |
| **本机 / 应用商店** | 代码所在地；上架与部署仍要你 |

橘猫**不替代** Codex、Claude Code、Cursor，只让它们的任务更小、可核对。

---

## 在你电脑上发生什么

```text
  普通人的回答
  + 可选的项目扫描（默认只读）
           │
           ▼
  本地规划（这一步不调云端 AI API）
           │
           ▼
  计划与记录（.jumao/、tasks/ 等）
           │
           ▼
  你把计划交给 AI 编程工具
           │
           ▼
  可选：核验 AI 的完成说法
```

关键属性：

- **默认本地** — 规划不依赖橘猫云或模型 Key。  
- **默认只读源码** — 检查与规划阶段。  
- **明确交接** — 通常是 `tasks/jumao-agent-plan.md` 加一段可粘贴说明。  
- **不偷偷发布** — 上线、付费、生产数据仍由人确认。

---

## 这里的「规划」指什么

橘猫做规划时，不是一个聊天机器人在猜你的产品。

它跑的是一套**固定的本地专业检查清单**（产品、隐私、发布风险等），分组展示：
哪些用上了、哪些跳过了、哪些要等你拍板。

你可能看到「8 组 / 44 个角色」——请把它们理解成**有名字的审查视角**，不是
44 个大模型在并行写代码。

角色常见状态：

| 状态 | 人话 |
|------|------|
| completed | 这件事相关，并留下了有用说明 |
| skipped | 当前没有触发条件或证据 |
| blocked | 缺只有你能做的决定 |
| failed | 这一项检查或写入没跑完 |

## AI 写完代码之后：完成回执与核验

好的交接会要求编程工具留下**完成回执**（做完了什么、卡在哪、验证过什么、有没有
碰真实世界）。

`jumao verify` 可以读回执，并对照：

- 它能看到的改动（例如通过 git），以及  
- 可选地重跑项目自己的测试。

因此完整核验只应对**你信任的项目**——测试也是代码。只想静态看时用
`--no-run-checks`。

---

## 橘猫不是什么

- 不是替你做产品判断  
- 不是保证 AI 一定听话（你仍要审）  
- 不是应用商店或支付通道  
- 不是本 Preview 里的「云端 AI 公司」产品
